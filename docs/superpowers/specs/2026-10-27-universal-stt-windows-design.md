# Universal STT для Windows — дизайн

Дата: 2026-10-27
Статус: на согласовании

## 1. Зачем

Нужно десктопное Windows-приложение, которое превращает любую запись — аудио или
видео — в размеченную по спикерам транскрипцию, полностью локально. Пользователь
открывает приложение, перетаскивает файл, видит прогресс, затем читает текст рядом
с таймлайном, переименовывает спикеров, сохраняет проект и экспортирует документ
или нарезку аудио.

База — `fatdata-stt`: там уже проверены модели, порядок шагов и правило привязки
реплик к спикерам. Но это Python-сервер (Photon/Kestrel, torch, NATS, SQLite), его
нельзя встроить в Rust-приложение. Поэтому переносим не код, а решения: Who для
диаризации, Parakeet для ASR и «спикер реплики = дорожка с максимальным
перекрытием по времени».

Публичный некоммерческий проект на GitHub, portable-сборка, воспроизводимая в
GitHub Actions после локальной проверки.

## 2. Цели

- Один portable-архив для Windows x64: запускается без установки, без Python,
  без Node, без внешних утилит в PATH.
- Любой формат, который декодирует FFmpeg: mp3, wav, flac, ogg/opus, m4a, aac,
  wma, mp4, mkv, mov, avi, webm, ts и т.д.
- Диаризация Who (ONNX int8) + транскрипция Parakeet Redux (GGUF).
- Автовыбор вычислительного бэкенда: CUDA (если доступен) → Vulkan (Intel, AMD,
  NVIDIA) → CPU. HIP на Windows не поддерживается и честно показывается как
  недоступный.
- Один файл за раз, без очереди: обработка идёт в реальном времени с фазами и
  процентом.
- UI: проект, таймлайн как в AIMP, цветные дорожки спикеров, автоскролл текста,
  видео-превью, переименование спикеров, контекстное меню, undo/redo, горячие
  клавиши.
- Проекты: сохранение, автосохранение, список недавних, переключение.
- Экспорт: DOCX/PDF полной транскрипции или выбранных спикеров; аудио-нарезка по
  спикерам или выбранным репликам.
- Современный тёмный интерфейс, аккуратная типографика, анимации без «дёрганья».

## 3. Не-цели

- Облако, аккаунты, синхронизация, телеметрия.
- Очередь пакетной обработки нескольких файлов.
- Пакетная обработка папок.
- Редактор видео, субтитры с прожигом, перевод.
- macOS/Linux-сборки в первой версии.
- Обучение или дообучение моделей.
- Идентификация личности по голосу между разными записями (voice library).

## 4. Анти-цели

Даже если технически работает, это провал:

- Приложение требует установленного Python, CUDA Toolkit или ffmpeg в PATH.
- Модели «докачиваются» в фоне без ведома пользователя, а без сети приложение
  мертво (portable-сборка должна быть офлайн).
- Транскрипция идёт минутами без прогресса и без возможности отмены.
- Спикеры в таймлайне и в тексте расходятся после переименования.
- Проект теряет правки при закрытии.
- Видео не перематывается синхронно с текстом.
- Установщик/архив требует прав администратора.

## 5. Установленные факты и ограничения

### 5.1. Who

- `who` — модель Desert Ant Labs. Windows-поддержка заявлена не для CLI, а для
  LiteRT/ONNX-сборок: «Android, Linux and Windows (LiteRT, on the CPU)».
- Публичная ONNX int8 сборка: `desert-ant-labs/who`, каталог `onnx-int8/`,
  revision `097d29a140dd19e220cff132e455e515d0e47e59`.
  Файлы: `encoder_6000.onnx`, `encoder_30000.onnx`, `queries_6000.onnx`,
  `queries_30000.onnx`, `voice_3256.onnx`, `who_embed.f16`,
  `who_mel_banks.f32`, `who_voice_banks.f32`, `who_meta.json`. Около 100 МБ.
- `who_meta.json` полностью описывает фронтенд (mel 23/80, 400/160 сэмплов,
  preemphasis 0.97, hamming, mean removal), окна (60 с и 300 с), пороги решения
  (presence 0.8, mask 0.5, rule mask), voice-окна и кластеризацию
  (average linkage, cosine 0.65, min solo 1 с).
- Референсная реализация пайплайна — Swift в `Desert-Ant-Labs/desert-ant-core`,
  `Sources/Who/` (~1300 строк): фронтенд, нарезка на куски, решение, voice
  embeddings, склейка спикеров. Её и портируем.
- Лицензия `desert-ant-labs-source-available-1.0`: embedding в приложение
  разрешён; бесплатно до 100k MAU на платформу на модель; нужна атрибуция;
  запрещено использовать выходы для обучения конкурирующей on-device модели.
  Публичный некоммерческий проект проходит.
- Ограничение модели: до 4 одновременных спикеров в пятиминутном куске, больше —
  через voice matching между кусками. Это принимается.

### 5.2. Parakeet Redux

- `moondream/parakeet-redux` — 1.58-bit (ternary) версия
  `nvidia/parakeet-tdt-0.6b-v3`, 25 европейских языков, CC-BY-4.0.
- Photon — Python-рантайм, в Rust не переносится. Берём `parakeet.cpp` (MIT):
  он читает Redux напрямую, публикует GGUF и C API.
- Модели `mudler/parakeet-cpp-gguf`, revision
  `c77726e46ceaab96b5a5a3328915edb44c73209d`:
  - `redux-packed.gguf` — 213 МБ, упакованный ternary, только CPU, offline.
  - `redux-q8_0.gguf` — 942 МБ, dense q8, годится для GPU.
  - `silero-vad-f16.gguf` — 1.3 МБ, MIT.
  - `parakeet-bundle-moondream-redux.gguf` — 215 МБ, Redux + Silero в одном
    файле; используем его для CPU-сборки вместо двух файлов.
- `parakeet.cpp` v0.6.1: Windows x64 сборки CPU, Vulkan, CUDA; C API
  (`include/parakeet_capi.h`), ABI 10; word timestamps с confidence,
  `transcribe_path_json`, VAD, batch, отмена через отдельный процесс/поток.
- C API не имеет callback прогресса. Поэтому режем аудио Silero VAD на куски
  ≤30 с и транскрибируем по куску: это даёт честный прогресс и возможность
  отмены между кусками.

### 5.3. Бэкенды

- Vulkan: работает на Intel, AMD и NVIDIA при свежих драйверах, один бинарник.
- CUDA: быстрее на NVIDIA, но требует CUDA runtime; делаем опциональным
  плагином, не обязательным для запуска.
- HIP/ROCm на Windows практически не существует; в UI показываем
  «HIP: недоступен на Windows», не притворяемся.
- Who всегда CPU (ONNX Runtime CPU EP) — так задумано моделью и достаточно
  быстро (сотни раз реального времени на десктопном CPU).

### 5.4. FFmpeg

- Декодирование любых форматов, извлечение 16 кГц моно WAV, probe, нарезка.
- Поставляется отдельным `ffmpeg.exe` (+ DLL для LGPL-сборки) рядом с
  приложением: это отдельная программа, а не библиотека, поэтому код приложения
  остаётся MIT.
- Берём LGPL-сборку BtbN. Для превью видео: H.264 через `h264_mf`
  (Media Foundation, Windows) с фолбэком на VP9/WebM; оба играются WebView2.
  Аудио-прокси: AAC в m4a (нативный энкодер FFmpeg, LGPL).
- Прокси создаётся один раз при импорте и хранится в проекте, поэтому
  воспроизведение и экспорт не зависят от кодека исходника.

### 5.5. UI-стек

Выбран Dioxus 0.7 desktop: весь код на Rust, вёрстка HTML/CSS, `<video>` и
`<audio>` работают нативно в WebView2, таймлайн рисуется на canvas, дизайн
делается без борьбы с нативными виджетами. WebView2 — системный компонент
Windows 10/11; в portable-архив кладём offline-загрузчик WebView2 на случай
отсутствия.

## 6. Рассмотренные подходы

### 6.1. UI

1. **Dioxus 0.7 desktop** — выбран. Весь код Rust, современный UI, видео и звук
   через WebView2, canvas-таймлайн. Плата: зависимость от WebView2 и более
   молодой экосистемы.
2. **Tauri 2 + React/TS** — зрелее и быстрее в дизайне, но фронтенд не Rust;
   отклонён из-за требования «всё на Rust».
3. **Нативный iced + wgpu** — без WebView2, но видео-кадры, таймлайн, текст и
   вёрстку пишем руками; срок и риск дизайна выше. Отклонён.

### 6.2. Движки

1. **Who ONNX + parakeet.cpp (Redux)** — выбран: ровно требуемые модели,
   Windows-сборки, лицензии совместимы, оба работают локально.
2. **parakeet-rs (ONNX Runtime) + Sortformer** — проще FFI, но нет Redux
   (только Parakeet TDT/Ultra) и нет Who; не выполняет требование.
3. **CLI `desertant` + parakeet.cpp** — невозможно: Windows-сборки CLI нет.

### 6.3. Упаковка

1. **Portable ZIP с моделями** — основная поставка, полностью офлайн, ~1.5 ГБ.
2. **Slim ZIP + докачка моделей** — дополнительный артефакт ~150 МБ.
   Обе собираются в CI; пользователь выбирает на странице релиза.

## 7. Архитектура

```
┌────────────────────────────────────────────────────────────┐
│ Dioxus UI (WebView2)                                       │
│  Welcome / Project / Settings / Export / Progress          │
│  canvas timeline · virtualized transcript · <video>        │
└───────────────▲───────────────────────────┬────────────────┘
                │ events (progress, result)  │ commands
┌───────────────┴───────────────────────────▼────────────────┐
│ App core (Rust)                                            │
│  ProjectStore · UndoStack · Settings · RecentProjects      │
│  ExportService · ModelManager · BackendProbe               │
└───────┬──────────────────────┬──────────────────────┬──────┘
        │                      │                      │
┌───────▼────────┐   ┌─────────▼─────────┐   ┌────────▼───────┐
│ MediaService   │   │ Diarizer (Who)    │   │ AsrService     │
│ ffmpeg/ffprobe │   │ ort + ONNX int8   │   │ parakeet.cpp   │
│ decode, proxy, │   │ CPU               │   │ CPU/Vulkan/CUDA│
│ waveform, cuts │   │                   │   │ Redux GGUF     │
└────────────────┘   └───────────────────┘   └────────────────┘
```

Всё в одном процессе. Тяжёлая работа — в отдельных `std::thread`, UI получает
события через `crossbeam-channel`, Dioxus `spawn` читает канал и обновляет
сигналы. Один активный job; повторный дроп во время работы отклоняется с тостом.

### 7.1. Структура репозитория

```
Cargo.toml                 # workspace
crates/
  app/                     # Dioxus desktop, точка входа
  core/                    # домен: проект, сегменты, undo, настройки
  media/                   # ffmpeg/ffprobe, probe, proxy, waveform, cuts
  diarize/                 # пайплайн Who: фронтенд, ONNX, решение, voice
  asr/                     # FFI parakeet.cpp, VAD-нарезка, JSON-парсинг
  export/                  # docx, pdf, srt/vtt/txt, аудио-нарезка
assets/
  fonts/                   # Inter, Noto Sans (кириллица)
  icons/
models/                    # не в git; попадает в portable ZIP
vendor/parakeet/           # include/parakeet_capi.h, лицензии, SHA
docs/
.github/workflows/release.yml
```

`app` зависит от `core`, `media`, `diarize`, `asr`, `export`. Домен не знает про
UI и про FFmpeg. Движки не знают про проект.

### 7.2. Выбор бэкенда

1. Если рядом есть `cuda/` плагин и `nvcuda.dll` грузится, а CUDA-сборка
   parakeet отвечает — `Cuda`.
2. Иначе пробуем `vulkan-1.dll`, перечисляем физические устройства с
   graphics+compute, грузим Vulkan-сборку parakeet — `Vulkan` c именем GPU.
3. Иначе `Cpu`.
4. HIP: определить наличие `amdhip64.dll` и показать «не поддерживается».

Настройки позволяют принудительно выбрать бэкенд и потоки. При смене бэкенда
модель перезагружается (`redux-packed` ↔ `redux-q8_0`).

### 7.3. Жизненный цикл обработки

1. `probe` — ffprobe: длительность, видео/аудио дорожки, кодек, разрешение.
2. `decode` — ffmpeg → `audio16k.wav` (моно, 16 кГц, s16le).
3. `proxy` — ffmpeg → `proxy.mp4` (H.264/AAC) или `proxy.m4a` (AAC).
4. `waveform` — peaks из WAV (бакеты 20 мс, min/max).
5. `diarize` — Who: 5-минутные куски, voice matching, turns.
6. `transcribe` — Silero VAD режет WAV на куски ≤30 с; каждый кусок →
   `parakeet_capi_transcribe_path_json`; таймстемпы сдвигаются на смещение.
7. `merge` — слова → предложения (пауза > 0.6 с, пунктуация, максимум 15 с),
   спикер предложения = максимальное перекрытие с turns Who.
8. `ready` — проект создан, UI открывает редактор.

Прогресс: общий = взвешенная сумма фаз (decode 5%, proxy 10%, diarize 20%,
transcribe 65%); внутри фаз — по обработанным секундам. ETA считается по
скорости текущей фазы. Отмена — флаг + завершение текущего куска; временные
файлы удаляются.

## 8. Домен и формат проекта

### 8.1. Модель

```rust
struct Project {
    schema: u32,                 // 1
    id: Uuid,
    title: String,
    source: SourceRef,           // путь, размер, mtime, хеш первых/последних 1 МиБ
    kind: MediaKind,             // Audio | Video
    duration: f64,
    language: Option<String>,    // определяется Parakeet
    speakers: Vec<Speaker>,      // id, name, color, index
    segments: Vec<Segment>,      // id, start, end, text, speaker_id, words
    turns: Vec<Turn>,            // сырые turns Who (для таймлайна)
    created_at, modified_at,
    export_defaults: ExportDefaults,
}

struct Speaker { id: Uuid, name: String, color: ColorIndex }
struct Segment { id: Uuid, start: f64, end: f64, text: String,
                 speaker_id: Option<Uuid>, words: Vec<Word> }
struct Word { start: f64, end: f64, text: String }
struct Turn { start: f64, end: f64, speaker_index: u32 }
```

Спикеры нумеруются по первому появлению, имена по умолчанию «Спикер 1…N»,
цвета — из фиксированной палитры из 8 цветов, повторяются после 8.

### 8.2. Файлы проекта

Проект — папка `<имя>.ustt/`:

```
project.json        # домен выше, атомарная запись (tmp + rename)
media/proxy.mp4     # или proxy.m4a
media/audio16k.wav  # нужен для экспорта нарезок и waveform
media/waveform.bin  # f32 min/max пары
```

Исходный файл не копируется: хранится ссылка. Прокси и WAV делают проект
самодостаточным для чтения и экспорта; если исходник пропал, проект всё равно
открывается (показываем «исходник недоступен», экспорт работает).

Новый проект создаётся автоматически при импорте:
`%USERPROFILE%\Documents\Universal STT\<slug>-<YYYY-MM-DD>.ustt`. Если папка
недоступна (read-only, OneDrive-конфликт), предлагается выбрать место сразу.
«Сохранить как…» доступно всегда; путь можно сменить до начала обработки.

Недавние проекты: `%APPDATA%\UniversalSTT\recent.json`, до 12 записей, битые
пути удаляются. Настройки: `%APPDATA%\UniversalSTT\settings.json`.

### 8.3. Undo/redo

- Все мутации домена идут через `Command` и `apply`.
- Стек снимков `Project` (clone) до 100 шагов; для больших проектов — обратные
  команды вместо снимков.
- Undo/redo: `Ctrl+Z` / `Ctrl+Shift+Z`, пункты в контекстном меню.
- «Грязный» флаг, автосохранение через 5 с после последней правки, `Ctrl+S` —
  немедленно, при закрытии — диалог, если не сохранилось.

## 9. UI

### 9.1. Экраны

1. **Welcome** — дропзона «Перетащите аудио или видео», кнопка выбора файла,
   список недавних проектов с датой и длительностью, настройки.
2. **Processing** — имя файла, фаза, процент, ETA, «Отменить». После готовности
   автоматически открывается проект.
3. **Project: аудио** — сверху панель спикеров; по центру транскрипт на всю
   ширину; снизу таймлайн AIMP-стиля с волной, цветными дорожками спикеров,
   playhead, клик = seek; под таймлайном транспорт.
4. **Project: видео** — рабочая область делится 50/50: слева транскрипт, справа
   `<video>` с превью; таймлайн снизу общий.
5. **Export** — модалка: формат (DOCX/PDF/SRT/VTT/TXT), спикеры чекбоксами,
   таймстемпы вкл/выкл, аудио-нарезка (по спикерам / по выбранным репликам,
   формат wav/m4a), папка назначения.
6. **Settings** — бэкенд и GPU, потоки, модели и их наличие, язык, тема,
   автосохранение, горячие клавиши.

### 9.2. Таймлайн

- Canvas: волна (min/max), поверх — полупрозрачные полосы turns спикера,
  цвет = спикер; сегменты без спикера — серые.
- Playhead, hover-время, выделение диапазона мышью (для экспорта куска).
- Клик — seek; drag — scrub; колесо — зум по времени; `Shift`+колесо —
  горизонтальный скролл.
- Во время проигрывания — плавное движение playhead (rAF), активный сегмент
  подсвечивается и автоскроллится.

### 9.3. Транскрипт

- Строки: время, цветная метка спикера, текст. Ширина на всю панель.
- Виртуализация: рендерим только видимые строки (часы аудио — десятки тысяч
  слов; DOM не должен пухнуть).
- Клик по строке — seek на начало; двойной клик — редактирование текста
  (правка текста тоже undoable).
- Во время проигрывания активная строка подсвечивается; автоскролл плавный;
  ручной скролл ставит автоскролл на паузу и показывает кнопку «К текущей».
- Панель спикеров сверху: чипы с цветом и именем, inline-переименование,
  счётчик времени; клик по чипу — фильтр/подсветка (не скрывает по умолчанию).

### 9.4. Поведение плеера

- `<audio>`/`<video>` элемент с прокси-файлом.
- `Space` — play/pause, `←/→` — ±5 с, `Shift+←/→` — ±30 с, `Home/End`.
- Перемотка кликом по таймлайну или строке работает и на паузе, и во время
  проигрывания.
- Скорость 0.75/1/1.25/1.5/2.
- Громкость и mute запоминаются.

### 9.5. Дизайн

- Тёмная тема по умолчанию, светлая — опция.
- Палитра: графит/уголь для фона, один акцент, 8 различимых цветов спикеров
  (проверены на дальтонизм).
- Шрифт Inter (латиница/кириллица) в архиве, fallback — Segoe UI.
- Радиусы 10–12 px, мягкие тени, 120–160 мс easing на hover/панели; никаких
  «прыжков» layout.
- Иконки — встроенный SVG-набор, без внешних шрифтов.
- Локализация RU/EN, по умолчанию язык системы; строки в одном файле-словаре.

## 10. Экспорт

### 10.1. Текст

- Источник — текущее состояние проекта (после переименований и правок).
- Фильтр: все спикеры или выбранные.
- DOCX (`docx-rs`): заголовок, дата, длительность, спикеры; абзацы
  `[HH:MM:SS] Имя: текст` (таймстемпы опционально).
- PDF (`printpdf`): та же структура, встроенный Noto Sans (кириллица),
  ручной перенос строк, нумерация страниц.
- SRT/VTT/TXT/Markdown — бонусом, тем же фильтром.
- Имя файла по умолчанию: `<title> — <дата>.<ext>`.

### 10.2. Аудио

- Режимы:
  1. «По спикерам» — один файл на спикера, куски склеиваются с паузой 0.4 с.
  2. «Выбранные реплики» — один файл из выбранных сегментов (checkbox в
     транскрипте / выделение на таймлайне).
- FFmpeg: `atrim` + `concat`, выход wav pcm_s16le или m4a AAC.
- Экспорт идёт из `audio16k.wav`, поэтому не зависит от исходного кодека.
- Прогресс и отмена — как у обработки.

### 13.2. Локальная приёмка под Wine/Proton-GE

Целевые ОС — Windows 10 и 11. Отдельной Windows-машины нет, поэтому приёмка идёт
в двухполосном режиме.

**Полоса A — UI и поведение (основная, быстрая).** Dioxus-приложение собирается
и для web-таргета. Playwright гоняет реальные сценарии в Linux-Chromium против
того же Rust-ядра с CPU-движками: welcome, прогресс, проект, переименование,
undo, автоскролл, экспорт. Это проверяет логику и вёрстку без Wine.

**Полоса B — Windows-шелл под Wine/Proton-GE.** Portable ZIP запускается через
Proton-GE (или чистый Wine 11) в отдельном префиксе. Один раз в префикс
ставится portable Edge WebView2 Runtime
(`MakaiForge/webview2`, ~193 МБ) и VC++ Redistributable. Проверяем: запуск без
администратора, drag&drop, `<video>`/`<audio>` (кодеки Edge), Vulkan-бэкенд
через winevulkan, экспорт, перезапуск с недавними проектами.
Известное ограничение: официальной поддержки WebView2 в Wine нет, работают
community-сборки; поэтому полоса A обязательна, а различия шелла фиксируются в
release notes.

**Полоса C — движки на Linux.** `diarize` и `asr` тестируются на CPU-сборке
parakeet.cpp и ONNX Runtime локально: те же модели, те же данные, другой шёлл.
Это ловит ошибки пайплайна до упаковки.

Если WebView2 в конкретной связке Wine/Proton не поднимается, это блокер
релиза: приложение не считается проверенным, пока полоса B не проходит.

**Чек-лист полосы B**

- [ ] Запуск portable ZIP без установки и без прав администратора.
- [ ] Drag&drop mp4 (H.264), mkv (HEVC), mp3, flac, opus, wav.
- [ ] Диаризация 2–4 спикеров, переименование, сохранение, повторное открытие.
- [ ] Видео: синхронная перемотка текста и превью, автоскролл, пауза автоскролла.
- [ ] Undo/redo, Ctrl+S, закрытие с несохранёнными правками.
- [ ] Экспорт DOCX/PDF (кириллица), выбранные спикеры, аудио по спикерам и по
      репликам.
- [ ] Бэкенды: Vulkan на доступном GPU, CPU fallback, CUDA-плагин при наличии.
- [ ] Отсутствие сети: всё, кроме slim-докачки, работает офлайн.

## 14. Риски

| Риск | Что делаем |
|---|---|
| Who ONNX не сходится с эталоном | порт по Swift-референсу, тест на эталонных mel/логитах, сверка turns на фикстуре |
| parakeet.cpp ABI/краш в процессе UI | изоляция: движок в отдельном потоке, все ошибки через код возврата, `catch_unwind` вокруг FFI, версия ABI проверяется при загрузке |
| WebView2 отсутствует | offline-загрузчик в архиве, понятный экран с кнопкой установки |
| Модели 1.5 ГБ, GitHub лимит 2 ГБ на ассет | два архива, сжатие, при необходимости — split/Release assets |
| Долгая обработка 3-часового видео | VAD-куски и прогресс, отмена, оценка ETA; прокси кодируется в фоне после старта диаризации |
| Лицензия Who | атрибуция, некоммерческий проект, бесплатный порог 100k MAU; модели не в git |
| Нет Windows-машины для локальной проверки | приёмка в двух полосах: web-таргет + Wine/Proton-GE с portable WebView2; полоса B — блокер релиза |
| WebView2 не работает в Wine/Proton | portable runtime + VC++ Redist, проверка на старте; при провале — блокер, обсуждаем смену UI-стека |
| Vulkan-драйверы старые | CPU fallback с packed Redux, предупреждение в Settings |
| Кривые таймстемпы на музыке/тишине | Silero VAD отсекает не-речь, сегменты без речи не создаём |

## 15. Мои решения (проверить при чтении)

1. UI RU+EN, по умолчанию язык системы. Публичный проект — английский README,
   русский раздел.
2. Исходный файл не копируется в проект; в проекте лежат прокси и WAV.
3. Автосохранение через 5 с, undo на 100 шагов.
4. Прокси видео — H.264 (Media Foundation) с фолбэком на VP9/WebM.
5. Portable ZIP — основная поставка, slim — дополнительная.
6. CUDA: в первой версии обязательный архив — Vulkan + CPU. Проба CUDA и
   загрузка плагина реализуются сразу, но сам плагин — отдельный опциональный
   архив, не блокирует релиз.
7. Код MIT, модели по своим лицензиям, атрибуция в About/NOTICE.
8. Имя приложения/репозитория — `Universal STT` / `universal-stt-windows`.
   Проект — пет-проект для личного использования, публичный и некоммерческий;
   это явно написано в README и About.
